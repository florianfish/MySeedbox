# CLAUDE.md

## Project

MySeedbox: Android app (Kotlin, Jetpack Compose, Material 3) to monitor and control any seedbox (host-agnostic): qBittorrent, Radarr, Sonarr, Prowlarr. Requests are handled by Jellyseerr, so the app does not duplicate search/add. UI strings and code comments are in French — keep it that way.

## Build

- No Gradle wrapper: system `gradle` 9.9.1, JDK 17, compileSdk 37 / targetSdk 34 / minSdk 26. AGP 9 built-in Kotlin: `org.jetbrains.kotlin.android` is only declared `apply false` in the root build, never applied in `:app`.
- CI: thin callers of the reusable workflows in the public repo `florianfish/Forge-Apk` (`android-build.yml`, `android-release.yml`, `@main`, `gradle-version: 9.9.1`, `apk-name: MySeedbox`). Change CI behaviour there. Debug APK fixed link: `releases/download/debug/MySeedbox-debug.apk`.
- No tests, no lint config.

## Architecture

Single module `:app`, package `fr.florian.seedbox`. No networking library: `HttpURLConnection` + `org.json`, blocking calls run on `Dispatchers.IO`.

- `Http.kt` — `Http.request` / `Http.check` (non-2xx → `HttpException` with a French message), `Throwable.friendly()` for user-facing errors, `String.asBaseUrl()` (adds `https://`, trims `/`).
- `Settings.kt` — `Service` enum, `ServiceConfig(url, user, secret)` (secret = API key, or qBittorrent password). URLs in plain SharedPreferences, secrets AES-GCM encrypted with an Android Keystore key (`allowBackup=false` because the key doesn't survive a restore). Never hard-code addresses or keys.
- `QBittorrent.kt` — WebUI API v2. Cookie login (all `name=value` pairs of Set-Cookie are kept, since the cookie name varies between versions), cached per server+user in a companion map; re-login on 401/403. `Referer`/`Origin` headers are mandatory (CSRF). Pause/resume try qBittorrent 5's `stop`/`start` first, then fall back to `pause`/`resume` on 404.
- `Arr.kt` — Radarr/Sonarr API v3 and Prowlarr API v1 with `X-Api-Key`: system status, health, disk space, queue, calendar, recent imports (`history?eventType=3`, grouped by movie / series), indexers + indexer status.
- `Ui.kt` — `Loader` / `rememberLoader` (load on IO, optional periodic refresh only while RESUMED), `LoadedList` (pull-to-refresh + spinner + error card), formatting helpers (`bytes`, `speed`, `duration`), custom icons (`AppIcons`) for those missing from material-icons-core.
- `TorrentsScreen.kt` — Torrents tab: search (accent/punctuation-insensitive, all words), sort (`TorrentSort` + « Ordre inverse », kept in prefs `torrents_sort*`), state chips + category / tag dropdown chips (null = all, "" = none), long press = multi-select with a `SelectionBar` (pause, reprise, tout sélectionner, catégorie via `setCategory`, déplacer via `FolderPicker`, supprimer via `DeleteTorrentDialog(list)`); group calls pass `hashes()` joined by `|`.
- `Screens.kt` — tabs: Imports (Radarr+Sonarr queues merged), Calendrier (30 days), État. Tabs also include Récents (between Imports and Calendrier). Multi-service screens use `gather` (internal, shared with `RecentScreen.kt`), so one failing service shows an error card without hiding the others.
- `RecentScreen.kt` — « Récents » tab: Films / Séries chips, 3-column poster grid built from chunked rows inside `LoadedList` (keeps pull-to-refresh). Cards show a resolution badge, size and language codes; tapping one opens a `ModalBottomSheet` (key kept in `rememberSaveable`) with media info and one card per release (`ImportEvent`s from the history record: quality, languages, custom formats, `data.size`, `data.releaseGroup`, `data.downloadClientName`, `sourceTitle`).
- `Posters.kt` — poster loading without an image library: `PosterRef` (plain class so the API key in its headers never shows in a `toString`), `Posters` (LruCache 32 MB, 4 parallel downloads, inSampleSize to ~300 px, failures remembered), `Poster` composable (2:3). Source: the *arr `mediacover/{id}/poster-250.jpg` with `X-Api-Key`, fallback to the image's `remoteUrl` (TMDB/TVDB, https only, no key sent). `Http.bytes` fetches binary bodies.
- `AddTorrentScreen.kt` — add a torrent (magnet/URL or `.torrent` file) with category and destination; `FolderPicker` browses the seedbox through qBittorrent 5's `app/getDirectoryContent` (`mode=dirs`). `add` sends multipart with `autoTMM=false` when a path is set, and both `paused` (v4) and `stopped` (v5). `MainActivity` turns VIEW magnet / VIEW `.torrent` / SEND intents into `Incoming` (activity is `singleTop`, `onNewIntent`).
- `TorrentDetailScreen.kt` — opened by tapping a torrent card (`detailHash` in `MainActivity`): header with actions (pause/reprise, vérifier, réannoncer, déplacer via `FolderPicker` + `setLocation`, supprimer via the shared `DeleteTorrentDialog`) and tabs Infos / Fichiers (checkbox = file priority 0/1) / Trackers (DHT/PeX/LSD pseudo-entries hidden) / Pairs (`sync/torrentPeers`). Refreshes every 5 s and closes itself when the torrent no longer exists.
- `Prowlarr.kt` / `ProwlarrScreen.kt` — dedicated Prowlarr screen (API v1), opened from the Prowlarr card in État (`showProwlarr` in `MainActivity`). Tabs Indexeurs (enable/disable via `PUT /indexer/{id}` with the full resource kept in `ProwlarrIndexer.raw`, `forceSave=true` only when disabling; per-indexer `POST /indexer/test`; 400 validation messages surfaced), Statistiques (`indexerstats`, 7 d / 30 d / all, sortable), Historique (`history` eventType 1+2, RSS excluded; `data` keys read case-insensitively), Applications (read-only sync level). `Http.request` takes a `json` body. Manual search stays out of scope (Jellyseerr).
- `LogsScreen.kt` — *arr logs (`Arr.logs`: `/log`, sorted by time, `level` + legacy `filterKey/filterValue`): Erreurs / Avertissements / Tout chips, « Afficher plus » grows the page size (so a refresh reloads everything shown, using `Loader.loading`), cards expand to the full message + exception in a `SelectionContainer` with « Copier ». Radarr/Sonarr cards in État open it (`logsService` in `MainActivity`); Prowlarr gets a « Journaux » tab (`LogsList`).
- `SettingsScreen.kt` — one form per service with « Tester » (calls the version endpoint) and « Enregistrer », plus « Sauvegarde » (export / import through the Storage Access Framework, so Google Drive works without OAuth).
- `Backup.kt` — configuration backup file (`.seedbox`, JSON envelope): the whole content (URLs included) is AES-256-GCM encrypted with a key derived from a user password (PBKDF2WithHmacSHA256, 600 000 iterations, random salt; min. 10 characters). The header (format, version, iterations) is the GCM AAD, so a modified file or a wrong password fails the same way. The password is never stored; `CharArray`s are wiped after use. Bump `VERSION` on any format change and keep reading older versions.
- `AppLock.kt` — app lock (`androidx.biometric`, `BIOMETRIC_WEAK or DEVICE_CREDENTIAL`), **on by default**, ignored when the phone has no screen lock. Lock state is process-wide: asked on each launch, stays unlocked while the app is open or in background (by design, no delay); relocks only when the activity finishes for good (`onDestroy` with `isFinishing`, not a rotation) or the process dies. `LockScreen` is drawn over `App`, which stays composed (state and activity results kept) with its semantics cleared. `MainActivity` is a `FragmentActivity` for `BiometricPrompt`. `LockSection` in the settings.
- `Theme.kt` — `Appearance` (theme mode Système / Clair / Sombre + Material You toggle, in prefs, observable state), `AppTheme`, `AppearanceSection` for the settings. `MainActivity` re-runs `enableEdgeToEdge` with the chosen darkness so system bar icons follow the app theme, not the system one.
- `MainActivity.kt` — top bar with version, bottom navigation; settings open automatically when nothing is configured.
